# 读懂 GNSS 串口数据：DX-GP23 的 NMEA0183 协议入门

> **读者**：刚接触 GNSS、UART 和 NMEA 的学习者。
>
> **资料来源**：`DX-GP23-NMEA0183协议规范.pdf`，版本 1.0，2024-07-30。
>
> **阅读边界**：本文只依据该 PDF 中列出的消息格式、字段、示例和状态说明整理。PDF 页眉写作“`NMEA0813`”，文件名及消息内容指向 NMEA0183；本文按文件名使用“**NMEA0183**”称呼，不能据此替厂商更正页眉。
>
> **证据标签**：`confirmed` 表示 PDF 直接给出的内容；`inferred` 表示根据已给格式作出的学习/实现推导；`unverified` 表示资料未确认或无法推广到其他模块的边界。

第一次看到 GNSS 串口输出时，最容易产生两个误解：一是把每一行文本都当作位置；二是只盯着某一个字段就判断“定位好不好”。实际上，一条 NMEA 语句只报告定位状态的一部分。要读懂它，需要把“报文长什么样”“每类语句回答什么问题”“怎样把多条语句组合起来”连成一条线。

本文使用资料中的 GGA 示例作为起点：

```text
$GNGGA,073028.600,2236.40101,N,11349.73472,E,1,19,0.8,14.2,M,-4.0,M,,*6E<CR><LF>
```

---

## 一、这是什么？——NMEA 在报告哪些 GNSS 信息

### 1. 一条语句的共同骨架

资料中所有消息都遵循相近的文本结构：

```text
$--XXX,field1,field2,...*CS<CR><LF>
│ │  │                       │  └─ 回车与换行
│ │  │                       └──── 两位十六进制 XOR 校验和
│ │  └──────────────────────────── 消息类型，例如 GGA、RMC
│ └─────────────────────────────── 发送器/系统标识占位
└───────────────────────────────── 一帧开始
```

|部分|含义|DX-GP23 资料中的说明|
|--|--|--|
|`$`|语句开始|校验和计算时不包含该字符|
|`--`|系统标识|资料将北斗导航卫星系统（BDS）标识为 `BD`；不同示例也出现 `GN`、`GP`|
|`XXX`|消息类型|例如 GGA、GSA、RMC；决定后续字段如何解释|
|`,`|字段分隔符|空字段仍占据自己的位置，不能删除逗号|
|`*CS`|校验和|`$` 与 `*` 之间、但不含二者的所有字符逐字节 XOR 结果|
|`<CR><LF>`|结束符|回车与换行，表示一帧文本结束|

> **解析提示（inferred）**：示例中前缀会变化，因此程序应先根据消息类型后缀分发，例如识别 `GGA`、`RMC`，而不是把输入固定为某一个完整前缀。

### 2. 先建立一张“消息职责地图”

十种消息并不是十份互不相关的数据。把它们按问题分类后，学习会轻松许多。

|你想知道什么|首要消息|辅助消息|它们回答的问题|
|--|--|--|--|
|位置是否存在、经纬度和高度|`GGA`|`GLL`、`RMC`|当前坐标、位置有效性、定位质量、卫星数和高度|
|运动得多快、朝向哪里|`RMC`|`VTG`、`DHV`|对地速度、航向、三维/地面方向速度|
|有哪些卫星、是否参与解算|`GSA`|`GSV`|已用于定位的卫星、可见卫星、DOP 与信号信息|
|UTC 时间和日期|`RMC`|`ZDA`|UTC 时刻、日期及完整年份|
|测量误差与模块告警|`GST`|`TXT`|伪距误差统计、天线开路/短路等文本信息|

### 3. 坐标不是十进制度，而是“度 + 分”

GGA、GLL、RMC 都使用相同的坐标表达：

| 坐标  | PDF 格式        | 示例              | 解读                           |
| --- | ------------- | --------------- | ---------------------------- |
| 纬度  | `ddmm.mmmmm`  | `2236.40101,N`  | 前两位为度，后续为分；`N` 为北半球，`S` 为南半球 |
| 经度  | `dddmm.mmmmm` | `11349.73472,E` | 前三位为度，后续为分；`E` 为东半球，`W` 为西半球 |

转换为十进制度的计算是：

```text
十进制度 = 度 + 分 / 60
南半球（S）或西半球（W）再取负值
```

因此，资料中的坐标可换算为：

```text
2236.40101,N   = 22 + 36.40101 / 60  = 22.6066835° N
11349.73472,E  = 113 + 49.73472 / 60 = 113.8289120° E
```

> 上述换算是对 PDF 所给“度分”格式作出的数学推导（inferred），不是模块额外输出的字段。

### 4. 五类最常见数据

|数据类别|相关字段|常见单位或格式|初学阶段的关注点|
|--|--|--|--|
|时间|`UTCtime`、`date`、`day/month/year`|`hhmmss.sss`、`ddmmyy`、四位年|UTC 不是本地时间；ZDA 的本时区字段在本模块中不支持|
|位置|`lat/uLat`、`lon/uLon`、`msl`|度分、米|坐标方向和高度参考对象都不能漏掉|
|有效性|`FS`、`valid`、`status`、`mode`|数字或字符枚举|数据“有字段”不等于位置“有效”|
|运动|`spd`、`cog`、`sog`、`kph`、`speed3D`|节、km/h、m/s、度|要区分对地速度、真航向、磁航向和 ECEF 方向速度|
|卫星/精度|`SVID`、`C/No`、`PDOP/HDOP/VDOP`、`RMS`|dB-Hz、无量纲、米|“看见卫星”与“用于定位”不是同一件事|

## 二、为什么？——为什么要交叉看状态、卫星和精度

### 1. 为什么不能只依赖一条语句

DX-GP23 在不同语句中分别给出不同层面的有效性。它们不是简单重复，而是互补。

|消息|字段|有效状态|无效或特殊状态|
|--|--|--|--|
|`GGA`|`FS` 定位质量|`1`：SPS 定位有效|`0`：不可用/无效；`6`：估算/航位模式，仅 NMEA 2.3 及以上有效|
|`GLL`|`valid`|`A`：数据有效|`V`：数据无效|
|`RMC`|`status`|`A`：数据有效|`V`：接收机警告，数据无效|
|`GSA`|`FS` 定位状态|`2`：2D；`3`：3D|`1`：定位无效|

> **使用建议（inferred）**：将一份位置快照用于应用前，可同时查看 RMC 的 `status`、GGA 的 `FS` 与 GSA 的 `FS`。它们同时满足有效条件时，结论比只看一个字段更稳妥。

### 2. 为什么 GSA 和 GSV 不可互相替代

这两个名字很像，却回答不同问题。

|对比项|`GSA`|`GSV`|
|--|--|--|
|核心含义|用于定位的卫星编号与 DOP|可见卫星的编号、仰角、方位角、载噪比|
|卫星范围|最多显示 12 个用于定位的卫星编号；不足补空|每条最多描述 4 颗可见卫星；可为 0 组|
|多系统行为|多系统联合工作时，每个系统的可用卫星对应一条 GSA|可见卫星多于 4 颗时，使用多条 GSV|
|精度信息|PDOP、HDOP、VDOP|C/No、仰角、方位角|
|初学者问题|“哪些卫星真正参与定位？”|“天空中能看见哪些卫星，信号怎样？”|

GSV 的多帧结构尤其重要。若首条是：

```text
$GPGSV,3,1,12,...
```

其中 `3,1,12` 的含义依次是“本批共 3 条”“当前第 1 条”“总共可见 12 颗卫星”。只有收到 `3,1,...`、`3,2,...`、`3,3,...`，这一批 GSV 才完整。

### 3. DOP 与 GST 都在谈精度，但不是同一种量

|指标来源|字段|PDF 中的含义|不要误解为|
|--|--|--|--|
|`GGA` / `GSA`|`HDOP`|水平精度因子|直接等于“横向误差多少米”|
|`GSA`|`PDOP`|位置精度因子|单独给出绝对定位误差|
|`GSA`|`VDOP`|垂直精度因子|海拔误差的直接米数|
|`GST`|`RMS`|定位过程中接收机伪距误差标准差的 RMS 值，单位米|对所有方向的完整误差椭圆|
|`GST`|`stdLat/stdLon/stdAlt`|纬度、经度、高度方向误差标准差，单位米|与 DOP 可直接互换|

资料中 DOP 的范围为 `0.5~99.9`。GST 中的椭圆半长轴、半短轴和朝向字段被明确标为“不支持”；解析时应允许它们为空，而不是把整条 GST 判成错误。

### 4. 为什么空字段与版本字段是正常现象

空字段不是天然的坏报文。PDF 至少给出了三类原因：

|消息|字段|空字段含义或限制|
|--|--|--|
|`GGA`|`diffAge`|未使用 DGPS 时为空|
|`RMC`|`mv`、`mvE`|本模块固定为空|
|`GSV`|卫星组的部分字段|未跟踪当前卫星时补空|
|`GST`|`stdDevMaj/stdDevMin/orientation`|本模块不支持|
|`ZDA`|`ltzh`、`ltzn`|本模块不支持，固定为 `00,00`|

同时，部分字段只在特定 NMEA 版本有效：

|消息|可选字段|资料中的版本条件|
|--|--|--|
|`GLL`|`mode`|NMEA 2.3 及以上|
|`RMC`|`mode`|NMEA 2.3 及以上|
|`RMC`|`navStatus`|NMEA 4.1 及以上|
|`GSA`|`systemId`|NMEA 4.1 及以上|
|`GSV`|`signalId`|NMEA 4.1 及以上|

### 5. 为什么校验和应当是第一道门

PDF 对所有消息使用同一规则：对 `$` 与 `*` 之间、且不含这两个字符的全部字符执行 XOR，结果以两位十六进制放在 `*` 后。

例如，GGA 示例末尾的 `*6E` 代表报文正文的 XOR 结果为 `0x6E`。在处理任何字段之前先检查校验和，能避免因传输损坏而把错误文本解释成真实坐标或状态。

## 三、怎么用？——从原始文本到可用的定位快照

### 1. 固定一条解析路径

无论之后用 C、Python 还是串口工具分析，建议按如下顺序思考：

```text
连续 UART 字节
  → 以 <CR><LF> 组帧
  → 确认 $ 起始、*CS 位置与长度
  → 计算 XOR 校验和
  → 按逗号切分，但保留空字段
  → 识别消息类型（GGA/RMC/GSV/...）
  → 按该类型的字段表转换单位与状态
  → 合并为一次带有效性标记的定位快照
```

其中“保留空字段”尤其关键。比如 RMC 的磁偏角和方向在该模块中固定为空：连续的 `,,` 仍然说明后面的 `mode` 或 `navStatus` 位于既定序号，而不是向前移动。

### 2. 手工拆解 GGA 示例

```text
$GNGGA,073028.600,2236.40101,N,11349.73472,E,1,19,0.8,14.2,M,-4.0,M,,*6E
```

|顺序|内容|读法|
|--:|--|--|
|语句头|`$GNGGA`|GGA 定位相关数据；`GN` 是示例中的系统标识|
|1|`073028.600`|UTC `07:30:28.600`|
|2-3|`2236.40101,N`|纬度 `22.6066835°N`（经度分换算）|
|4-5|`11349.73472,E`|经度 `113.8289120°E`（经度分换算）|
|6|`1`|定位质量：SPS 定位有效|
|7|`19`|定位卫星数|
|8|`0.8`|HDOP|
|9-10|`14.2,M`|相对大地水准面的天线海拔：14.2 米|
|11-12|`-4.0,M`|参考椭球面与大地水准面间距离：-4.0 米|
|13-14|`,`|DGPS 数据龄期/基站 ID；示例为空|
|校验|`*6E`|XOR 校验和|

### 3. 手工拆解 RMC 示例

```text
$GNRMC,073028.600,A,2236.40101,N,11349.73472,E,0.00,0.00,090724,,,A,V*00
```

|顺序|内容|读法|
|--:|--|--|
|语句头|`$GNRMC`|RMC，推荐的最小定位信息|
|1|`073028.600`|UTC `07:30:28.600`|
|2|`A`|数据有效|
|3-6|`2236.40101,N,11349.73472,E`|纬度、经度及方向|
|7|`0.00`|对地速度，单位节|
|8|`0.00`|对地真航向，单位度|
|9|`090724`|日期，格式 `ddmmyy`，即 2024-07-09|
|10-11|`,,`|磁偏角及方向；本模块固定为空|
|12|`A`|定位模式：自主模式|
|13|`V`|导航状态标识；资料说明 V 表示系统不输出导航状态信息|

### 4. 如何组装一批 GSV

将资料中的 `$GPGSV,3,1,12,...`、`$GPGSV,3,2,12,...`、`$GPGSV,3,3,12,...` 看成同一批数据：

1. 使用 `numMsg` 知道该批应有几条；
2. 使用 `msgNo` 将每条放到正确位置；
3. 使用 `numSv` 知道本批可见卫星总数；
4. 逐条取出最多四组 `SVID,ele,az,cn0`；
5. 缺少任何序号、超时或校验失败时，将该批标为不完整，而不是把它当完整天空视图。

第 5 条是面向软件实现的稳健性建议（inferred）；PDF 明确事实是“每条最多 4 颗可见卫星”和“多于 4 颗时需要多条 GSV”。

### 5. 四个学习练习

|练习|你的任务|预期结果|
|--|--|--|
|1. 找边界|在 GGA 示例中圈出 `$`、`*6E` 和 `<CR><LF>`|知道 XOR 只覆盖 `$` 与 `*` 之间|
|2. 换坐标|将 `2236.40101,N` 转为十进制度|`22.6066835°N` 左右|
|3. 判有效|给定 RMC `status=V`，再给 GGA `FS=1`|不应只因 GGA 有效就发布可信位置，应记录状态冲突|
|4. 组 GSV|收到 `3,1,12` 和 `3,3,12`，但没有 `3,2,12`|本批卫星视图不完整，不能按完整批次使用|

## 附录 A：十种消息的格式与字段组成

### A.1 GGA：时间、位置与定位质量

```text
$--GGA,UTCtime,lat,uLat,lon,uLon,FS,numSv,HDOP,msl,uMsl,sep,uSep,diffAge,diffSta*CS<CR><LF>
```

|字段|含义|示例|格式、单位或限制|
|--|--|--|--|
|`$--GGA`|消息 ID|`$GNGGA`|`--` 为系统标识|
|`UTCtime`|当前定位 UTC 时间|`073028.600`|`hhmmss.sss`|
|`lat`|纬度|`2236.40101`|前两位为度，后续为分|
|`uLat`|纬度方向|`N`|`N` 北半球；`S` 南半球|
|`lon`|经度|`11349.73472`|前三位为度，后续为分|
|`uLon`|经度方向|`E`|`E` 东半球；`W` 西半球|
|`FS`|当前定位质量|`1`|见附录 B|
|`numSv`|定位卫星数|`19`|`00~24`|
|`HDOP`|水平精度因子|`0.8`|`0.5~99.9`|
|`msl`|天线相对大地水准面的海拔|`14.2`|米；资料给出范围 `-9999.9~-99999.9`|
|`uMsl`|海拔单位|`M`|固定 `M`|
|`sep`|参考椭球面与大地水准面间距离|`-4.0`|`-` 表示大地水准面低于参考椭球面|
|`uSep`|间距单位|`M`|固定 `M`|
|`diffAge`|DGPS 差分数据龄期|空|未使用 DGPS 时为空|
|`diffSta`|差分参考基站编号|空|差分参考站 ID|
|`CS`|校验和|`6E`|XOR 结果|
|`<CR><LF>`|结束符|`<CR><LF>`|回车与换行|

### A.2 GLL：经纬度、时间与状态

```text
$--GLL,lat,uLat,lon,uLon,UTCtime,valid,mode*CS<CR><LF>
```

|字段|含义|示例|格式、单位或限制|
|--|--|--|--|
|`$--GLL`|消息 ID|`$GPGLL`|`--` 为系统标识|
|`lat/uLat`|纬度及方向|`2236.40101,N`|度分；`N/S`|
|`lon/uLon`|经度及方向|`11349.73472,E`|度分；`E/W`|
|`UTCtime`|当前定位 UTC 时间|`073028.600`|`hhmmss.sss`|
|`valid`|定位数据有效性|`A`|`A` 有效；`V` 无效|
|`mode`|定位模式|`A`|仅 NMEA 2.3 及以上；见附录 B|
|`CS`|校验和|`45`|XOR 结果|
|`<CR><LF>`|结束符|`<CR><LF>`|回车与换行|

### A.3 GSA：参与定位的卫星与 DOP

```text
$--GSA,smode,FS{,SVID},PDOP,HDOP,VDOP,systemId*CS<CR><LF>
```

|字段|含义|示例|格式、单位或限制|
|--|--|--|--|
|`$--GSA`|消息 ID|`$GNGSA`|`--` 为系统标识|
|`smode`|模式切换方式|`A`|`M` 手动强制 2D/3D；`A` 自动切换|
|`FS`|定位状态|`3`|`1` 无效；`2` 2D；`3` 3D|
|`{SVID}`|用于定位的卫星编号槽位|`11,13,...`|共 12 槽；多于 12 颗仅输出前 12；不足补空|
|`PDOP`|位置精度因子|`1.4`|`0.5~99.9`|
|`HDOP`|水平精度因子|`0.8`|`0.5~99.9`|
|`VDOP`|垂直精度因子|`1.1`|`0.5~99.9`|
|`systemId`|GNSS 系统 ID|`1`|仅 NMEA 4.1 及以上；见附录 B|
|`CS`|校验和|`0C`|XOR 结果|
|`<CR><LF>`|结束符|`<CR><LF>`|回车与换行|

### A.4 GSV：可见卫星信息

```text
$--GSV,numMsg,msgNo,numSv{,SVID,ele,az,cn0},signalId*CS<CR><LF>
```

|字段|含义|示例|格式、单位或限制|
|--|--|--|--|
|`$--GSV`|消息 ID|`$GPGSV`|`--` 为系统标识|
|`numMsg`|本批语句总数|`3`|每条最多输出 4 颗可见卫星；多于 4 颗需多条|
|`msgNo`|当前语句编号|`1`|从本批第一条到最后一条|
|`numSv`|可见卫星总数|`12`|表示本批可见卫星数量|
|`SVID`|卫星编号|`05`|与后续三个字段构成可重复卫星组|
|`ele`|卫星仰角|`37`|`0~90` 度|
|`az`|卫星方位角|`054`|`0~359` 度|
|`cn0`|载噪比 C/No|`17`|`0~99` dB-Hz；未跟踪时补空|
|`signalId`|GNSS 信号 ID|`0`|`0` 表示全部信号；仅 NMEA 4.1 及以上|

### C.2 初学者最容易犯的错误

|错误|正确做法|
|--|--|
|把 `2236.40101` 当作 `22.3640101°`|按“度 + 分/60”转换|
|看到一个空字段就认为整帧无效|先查该字段是否允许为空或不支持|
|把 GSV 可见卫星数当作 GSA 已用卫星数|分别理解“可见”与“用于定位”|
|收到 GSV 的第一条就更新完整卫星视图|根据 `numMsg/msgNo` 收齐一批再使用|
|只看 GGA 或 RMC 一个状态字段|交叉检查 GGA、RMC、GSA 的有效性|
|校验前就转换字段|先验证 `*CS`，再解释正文|
