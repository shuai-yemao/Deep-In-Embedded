# 📝driver 文件的设计思路

> 用一句话说清楚这个知识点是什么。

如何处理 bsp_xxx_driver 中内部实现的中断回调函数和 dma 中断回调函数与 adapter 层的芯片平台实际外部中断回调函数和 dma 回调函数的转接，以及 driver 中的中断回调函数如何处理异步处理和通知
## 实际意义

> 为什么会有该知识点？解决了什么实际问题？

本笔记的核心问题是：**中断向量表在芯片平台（Core/Adapter 层），但中断要触发的业务逻辑在外设驱动（BSP driver 层），两者如何解耦地对接？**

AHT21 驱动（[[AHT21的driver文件架构设计思路]]）用同步阻塞模式（发命令→等→读），不需要中断。但 MPU6050 不同——数据由 INT 引脚以 200Hz 触发，数据量大适合 DMA，必须走**异步中断驱动**路线。

### 1. 回调注册机制：adapter 转接，driver 响应

adapter 层通过函数指针注入，让 HAL 中断回调能"找到"对应的 driver 实例：

```
adapter: HAL_GPIO_EXTI_Callback(pin) → 查表 → driver.callbacks.data_ready()
driver:  收到回调 → 只做标志位 + 发信号量（平台无关代码）
```

**意义**：换 MCU 时只改 adapter 的查表逻辑，driver 层零改动。

### 2. 中断上下半部分离

ISR 执行期间同级和低优先级中断全部被阻塞。如果在 EXTI ISR 里直接跑姿态解算，SysTick 会被阻塞导致 FreeRTOS 时基偏移。

```
上半部 (ISR, <5μs):  清标志位 → 判断来源 → 发任务通知/信号量
下半部 (任务上下文):  阻塞等待 → DMA 读 FIFO → 校验 → 解算 → 发布
```

> 这与笔记 Q9（中断延迟）、Q2（少用中断）、Q8（ISR 不能超 2 tick）直接关联。

### 3. 同步原语选择

| 方式 | 优势 | 适用场景 |
|------|------|---------|
| 任务通知 | 比信号量快 ~45%，RAM 开销更小 | 中断→固定单任务（推荐） |
| 二值信号量 | 标准、简单 | 通用场景 |
| 消息队列 | 可携带数据 | 需要传数据的场合 |

> 对应笔记 Q&A 第 3 问："一定要用信号量吗？"

### 4. 多实例：一套 driver 驱动 N 个 MPU6050

通过查表 + 回调用户上下文（`user_data` 指向各自的 `mpu6050_driver_t`），每增加一个传感器只需加一行绑定配置。

> 这与 [[AHT21的driver文件架构设计思路]] 互补：AHT21 侧重"同步阻塞 + 资源注入"，MPU6050 侧重"异步中断 + 回调路由"。

## 应用场景

> 在实际中主要被用来做什么？

1. **无人机/机器人姿态解算**：MPU6050 INT 以 200Hz 触发 → ISR 发任务通知 → handler 任务 DMA 读 14 字节 → Madgwick AHRS 解算。DMA 传输期间 CPU 可并行处理上一帧数据。

2. **DMA 双缓冲高速采集**：循环模式 + 半完成/全完成中断，driver 处理缓冲前半段时 DMA 继续填后半段，实现零拷贝流水线。

3. **低功耗运动唤醒（WOM）**：MCU 在 STOP 模式（<10μA），MPU6050 检测到运动后 INT 唤醒 → adapter 路由到 driver → driver 判断真运动还是噪声 → 决定是否重新初始化采集。

4. **跨平台产品线**：driver 层 ~600 行（状态机、FIFO 解析、DMP、校准）在 STM32F4 / ESP32-S3 / GD32 间零改动复用，只换 adapter 层 ~150 行。

5. **Mock 中断 CI 测试**：注入模拟中断验证 driver 的回调路由、信号量发送、超时处理逻辑，PC 上跑 Unity 测试，无需硬件。

6. **多传感器时间同步**：MPU6050 + 磁力计 + 气压计的 INT 统一由 adapter 路由，在 ISR 上半部打时间戳，融合算法拿到时间对齐的多源数据帧。
